# Trade Newsline 발송용 HTML 자동 생성 (`/html변환`) — 설계 문서

- 날짜: 2026-07-07
- 상태: 승인됨 (김태헌)
- 목표: 뉴스레터 발송용 이미지맵 HTML을 IT 운영센터 SR 의존 없이 자체 제작

## 1. 배경

현재 프로세스: 커버(HWP→PDF)·이너 PDF 제작 → 이너 PDF를 Constant Contact에 업로드해 URL 확보 → HYPERLINK PPTX로 버튼-링크 매핑 표기 → KIWI 그룹웨어 SR로 IT 운영센터에 "HTML 변환 요청" → IT가 이메일용 JPG 제작·업로드(`kita.net/mailclub/NeDM/edm_YYYYMMDD.jpg`) 및 이미지맵 HTML 제작. 소요 약 1일.

HTML 구조 분석(12호 vs 13호 비교):
- 구조: 단일 이미지 + `<map>` 클릭영역 18개, euc-kr 인코딩
- 매 호 변경되는 값 4가지:
  1. 이미지 파일명 (`edm_YYYYMMDD.jpg`)
  2. Constant Contact 이너 PDF URL (UUID 경로)
  3. 각 섹션 링크의 `#page=` 번호
  4. 콘텐츠 길이에 따른 일부 버튼 y좌표 미세 이동 (예: 1065→1056)
- 고정 링크 10개(구독신청, 지난호 다시보기, kita.net 메뉴 4종, SNS 3종 등)는 좌표까지 사실상 동일 (나머지 8개는 CC 이너 PDF `#page` 링크)

## 2. 범위 결정 (사용자 확인 완료)

- **자동화 범위**: HTML 완전 자체 제작. IT에는 JPG 업로드만 요청(또는 SR에 완성 HTML 첨부).
- **좌표 방식**: 하이브리드 — 자동 감지 + 편차가 크면 이전 호 좌표 폴백 + 수동 검수.
- **실행 형태**: Claude 스킬 커맨드 (`/html변환`).

## 3. 구성 요소

### 3.1 스킬 정의 — `.claude/skills/html변환/SKILL.md`
- 호출: `/html변환 [커버 PDF 경로]`
- 대화형 진행: 발행일(이미지 파일명 날짜)·CC PDF URL 입력 → 좌표 감지 → `#page` 매핑 확인 → 미리보기 검수 → 최종 HTML 출력
- Claude가 스티칭 이미지를 직접 보고 버튼 위치를 보정하는 단계 포함

### 3.2 Python 헬퍼 — `scripts/newsletter_html.py` (PyMuPDF)
- `render`: 커버 PDF 각 페이지를 렌더링해 세로 스티칭 → 이메일용 JPG 생성 (폭은 기존 이미지 기준, 약 700px 계열)
- `build`: 좌표 템플릿 JSON + 호별 입력값(날짜, CC URL, page 매핑, 보정 좌표)으로 euc-kr HTML 조립
- `preview`: 로컬 이미지 참조 + 클릭영역 반투명 오버레이(+링크 라벨, 경고 영역 빨간색) 미리보기 HTML 생성
- 이 PC에 poppler 미설치 → PDF 렌더링은 PyMuPDF(pip 설치)로 처리

### 3.3 좌표 템플릿 — `scripts/templates/newsletter_map.json`
- 13호 HTML에서 추출한 기준 좌표 + 고정 링크 + 각 영역의 의미 라벨(예: "경제통상 핫이슈 자세히보기") 저장
- 매 호 확정 후 좌표를 갱신해 다음 호 기준값으로 사용

## 4. 좌표 결정 로직

1. 이전 호(템플릿) 좌표를 1차값으로 사용
2. Claude 비전으로 스티칭 이미지에서 "»자세히 보기" 버튼 등 실제 위치 감지 → y좌표 보정
3. 감지값-기준값 편차가 임계치(예: 세로 80px) 초과 시 기준값 유지 + 미리보기에 경고 표시
4. 사용자 미리보기 눈검수 → 확정

## 5. 매 호 워크플로우

```
커버 HWP → PDF 저장 (기존과 동일)
이너 PDF → Constant Contact 업로드 → URL 복사 (기존과 동일)
/html변환 실행 → 발행일, CC URL 입력 → #page 매핑 확인
→ 미리보기 검수 → "N호 html.html" + 이메일용 JPG 완성
→ IT에 JPG 업로드 요청 (파일명 edm_YYYYMMDD.jpg 명시)
```

## 6. 에러 처리

- 좌표 감지 실패/편차 초과: 이전 호 좌표 사용 + 미리보기 빨간 표시
- 커버 PDF 페이지 폭 불일치: 스티칭 전 폭 정규화, 불가 시 명시적 에러
- 필수 입력 누락(CC URL 등): HTML 생성 중단하고 요청

## 7. 열린 질문 / 리스크

- 커버 PDF가 38페이지로 나옴(HWP 내보내기 특성 추정). 실제 페이지 구조는 구현 1단계에서 렌더링으로 확인하고, 다르면 스티칭 로직 조정.
- 이미지 URL은 IT 업로드 후 확정 → SR 요청 시 파일명(날짜)을 명시하는 운영 규칙 필요.
- euc-kr 인코딩 유지 (발송 시스템 요구사항으로 추정). 생성 파일은 euc-kr로 저장.

## 8. 테스트 기준

- 13호 입력(커버 PDF + 13호 실제 값)으로 생성한 HTML이 실제 발송된 "13호 html.html"과 좌표·링크 모두 동등해야 함 (골든 테스트)
- 미리보기 HTML에서 18개 영역이 모두 버튼 위에 정확히 얹히는지 육안 확인
